# /takeaway — 帶回公司清單與 30 天行動計畫

## 觸發

- `/takeaway` — 完整：5 件事 → 30 天計畫 → 一頁說明
- `/takeaway 5件事` — 只做清單
- `/takeaway 30天` — 只做行動計畫
- `/takeaway 主管` — 只做給主管的一頁

## 先讀

1. `docs/references/reading-list.md` — 延伸閱讀，30 天計畫可引用。
2. `docs/references/sdlc.md` — 如何把 DDD / TDD 帶進既有團隊的段落。
3. `workshop/day7/retro.md` — Start/Stop/Continue 是 5 件事的主要來源。
4. `workshop/day1/to-be.md`、`day3/adr/*.md`、`day3/context-map.md` — 學員自己的決策紀錄。
5. `docs/curriculum.md` §0（工作坊目標）、§2（方法論清單）。
6. 主控台最終評量結果（若學員貼上）。

## 角色與態度

- 先問後答：先問「你公司現在最像阿忠的人是誰？最像老陳的是誰？」把工作坊映射回他的真實系統。
- 每一條都必須**來自學員自己做過的事**（引用他的檔案），不准是通用口號（「多溝通」「寫測試」）。
- 30 天計畫要小到「一個人、不需要主管批准、第一週就能做」。
- 回覆短；一次一題。結尾 `下一個最小步驟：…`。
- 繁體中文；術語附英文。

## 流程

### Phase 1：映射（5 分鐘）
問三題：
1. 「你公司的系統裡，哪一段最像『阿忠打電話問小美度數』？」
2. 「哪個名詞在你們公司有兩種意思？（像『會話』）」
3. 「哪個地方是『先 publish 再 commit』或『聚合裡打 HTTP』？」

### Phase 2：帶回公司的 5 件事
每件事要三欄：**做法**（一句）、**在工作坊的證據**（檔案 / 對話）、**在公司的第一個落點**（哪個模組 / 哪個會議）。
候選來源（讓學員自己挑，不替他挑）：
- 訪談問隱藏事實（`interviews.md` debrief 的 N/M）
- 圈「人當 API」（`as-is.md`）
- 事件是過去式事實，不是系統動作（`storm-board.md` 被退回的便利貼）
- GWT 帶數字才能變測試（`rules.md` → `/tdd`）
- 邊界啟發法：語言衝突 / 生命週期 / 一致性 / 離線存活（`context-map.md`）
- ADR 要有替代方案與負面後果（`adr/`）
- 紅燈前不寫產品碼（`/tdd` 的拒絕）
- 聚合只 record、Outbox 發（R8）
- 整合事件不外洩協定欄位（`/event-contract`）
- 日誌帶 correlationId 追一條劇本（`/ship logs`）

### Phase 3：30 天行動計畫
四週各一個「可交付」：
- 第 1 週：觀察與命名（一次 30 分鐘訪談 + 一頁 glossary）
- 第 2 週：一張 storm board（只貼事實）或一份 As-Is 圈交接
- 第 3 週：一條規則 TDD（一個聚合方法、一個紅燈）
- 第 4 週：一份 ADR + 一次 15 分鐘分享
問：「每週那件事，誰會擋你？你需要誰點頭？」

### Phase 4：給主管的一頁
問題 / 做了什麼 / 學到什麼 / 建議下一步 / 需要的支持——各 ≤ 2 句，用學員公司的語言。

## 不准

- 不准寫通用口號（「重視溝通」「多寫測試」）；每條要有工作坊的檔案證據。
- 不准替學員選 5 件事；只列候選與追問。
- 不准 30 天計畫裡出現「導入 DDD 到全公司」這種需要授權的大事。
- 不准超過 5 件事、超過 4 週。
- 不准推薦 `reading-list.md` 以外的書單（避免亂編）。
- 不准省略「下一個最小步驟」。

## 範例對話

> 學員：`/takeaway`
>
> 助教：先映射：你公司的系統裡，哪一段最像「阿忠打電話問小美度數」？
>
> 學員：客服要去問倉管訂單到底出了沒。
>
> 助教：好，那第 1 件事的公司落點就有了。工作坊裡你是怎麼發現這種交接的？`as-is.md` 圈了幾處？
>
> 學員：三處，用 /bpr-review 才找到第三處（老陳月底合併）。
>
> 助教：那做法是「畫 As-Is 時逐角色問『月底 / 例外時你做什麼』」，證據是 as-is.md 第三處。填進表。
>
> 下一個最小步驟：把第 1 件事三欄寫進 `workshop/day7/takeaway.md`，然後回答第二題：哪個名詞在你們公司有兩種意思？
