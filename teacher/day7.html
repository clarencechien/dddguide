# CI for the EV Charge Ops workshop branch workshop/clarence.
# One workflow serves both languages: the `config` job reads workshop/.config (LANG=node | LANG=python)
# and builds the matrix with ONLY that starter, so the other one (still on its Day 1 red test) never runs.
name: ci

on:
  push:
    branches: ["main", "workshop/**"]
  pull_request:

# A new push to the same branch cancels the run that is still going.
concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

permissions:
  contents: read

jobs:
  config:
    # Decide which starter to test. Fails loudly if workshop/.config is missing or says something else.
    runs-on: ubuntu-latest
    timeout-minutes: 2
    outputs:
      matrix: ${{ steps.pick.outputs.matrix }}
      lang: ${{ steps.pick.outputs.lang }}
    steps:
      - uses: actions/checkout@v4
      - id: pick
        run: |
          lang=$(grep -E '^LANG=' workshop/.config | tail -1 | cut -d= -f2 | tr -d '[:space:]')
          case "$lang" in
            node)   matrix='{"include":[{"lang":"node","dir":"starter/node"}]}' ;;
            python) matrix='{"include":[{"lang":"python","dir":"starter/python"}]}' ;;
            *) echo "::error::workshop/.config must say LANG=node or LANG=python (got '$lang')"; exit 1 ;;
          esac
          echo "lang=$lang"     >> "$GITHUB_OUTPUT"
          echo "matrix=$matrix" >> "$GITHUB_OUTPUT"

  test:
    # Unit + application tests of the chosen starter. Dependencies are cached per lockfile.
    needs: config
    runs-on: ubuntu-latest
    timeout-minutes: 15
    strategy:
      fail-fast: false
      matrix: ${{ fromJSON(needs.config.outputs.matrix) }}
    defaults:
      run:
        working-directory: ${{ matrix.dir }}   # every `run` below executes inside starter/<lang>
    steps:
      - uses: actions/checkout@v4

      # --- node -------------------------------------------------------------
      - if: matrix.lang == 'node'
        uses: actions/setup-node@v4
        with:
          node-version: 22                      # scripts/e2e/run.mjs relies on Node 22 type stripping
          cache: npm
          cache-dependency-path: starter/node/package-lock.json   # NOT the repo root
      - if: matrix.lang == 'node'
        run: npm ci
      - if: matrix.lang == 'node'
        run: npm test                           # package.json: "test": "vitest run"
      - if: matrix.lang == 'node'
        run: npm run typecheck                  # tsc --noEmit

      # --- python -----------------------------------------------------------
      - if: matrix.lang == 'python'
        uses: actions/setup-python@v5
        with:
          python-version: "3.11"
          cache: pip
          cache-dependency-path: starter/python/requirements.txt
      - if: matrix.lang == 'python'
        run: pip install -r requirements.txt
      - if: matrix.lang == 'python'
        run: pytest -q                          # pyproject.toml sets pythonpath = ["src"]

  contracts:
    # Integration-event contracts (curriculum §1.8): every example must validate against its schema.
    # Runs for both languages — the contracts are shared and language-neutral.
    runs-on: ubuntu-latest
    timeout-minutes: 5
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
      - run: node contracts/validate.mjs

  e2e:
    # Optional (day7.md 延伸): boot the Day 6 HTTP API on SQLite in the background and replay
    # the canonical afternoon 14:02 → 18:18 against it. Start commands come from workshop/day6/README-mvp.md.
    needs: [config, test]
    runs-on: ubuntu-latest
    timeout-minutes: 10
    strategy:
      matrix: ${{ fromJSON(needs.config.outputs.matrix) }}
    env:
      DB_PATH: /tmp/e2e.sqlite
      PORT: "3000"
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: ${{ matrix.lang == 'node' && 'npm' || '' }}
          cache-dependency-path: ${{ matrix.lang == 'node' && 'starter/node/package-lock.json' || '' }}
      - if: matrix.lang == 'python'

          python-version: "3.11"
          cache: pip
          cache-dependency-path: starter/python/requirements.txt

Quiz 五題參考答案

1 · route handler 內判斷憑證是否有效，違反哪個鏡頭？移到哪一層？

兩個鏡頭：六角（adapter 不做決策）與 DDD（授權是 R2，屬 Charging 的規則）。移法：StartCharging 處理器呼叫 AuthorizationService.isAuthorized(idTag) port 得到布林值，傳進 ChargingSession.start({ authorized })；聚合記錄 ChargingStartRejected(reason=Unauthorized)；handler 只把事件映射成回應碼（OCPP idTagInfo.status = Invalid；HTTP 4xx）。守住它的測試：R2 through the service: unknown idTag is rejected by the AuthorizationService port。

2 · CI 的 contracts job 在守什麼？有人拿掉 energyWh，哪個測試會紅？

守「契約沒有被默默改壞」——範例與 Schema 要一直對得上，而且程式產生的事件也要過。如果有人從 charging.session.completed.v1.schema.json 的 required 拿掉 energyWh，node contracts/validate.mjs 本身不會紅（範例還帶著 energyWh，少一個 required 不算違規）——會紅的是 Day 5 的 StopCharging output validates against charging.session.completed.v1 若加了 additionalProperties: false，以及下游 BillingDraftConsumer 的 creates one draft invoice INV-778 for session S-991 with 12.4 kWh（金額變 0）。反過來，如果把 energyWh 從範例拿掉，validate.mjs 立刻紅：$.payload: missing required "energyWh"。講師追問：這說明 contracts job 守的是哪個方向？（Schema 變嚴 → 範例紅；Schema 變鬆 → 要靠程式端測試。）

3 · PR 描述為什麼要連結 ADR-0002，而不只寫「MVP1 做了 Charging」？

「做了 Charging」是什麼，ADR-0002 是為什麼只做這些、否決了什麼、代價是什麼。Reviewer（與三個月後的自己）要能判斷取捨是否合理：為什麼不先做 Billing 合併出帳（Billing 需要顧客、費率表、停車事件，三者 MVP1 都沒有）、為什麼 Dispatch 只是 stub。Sprint 2 開工時也才知道哪些假設可以推翻——本頁 ADR-0003 就是「對帳」時發現 0002 一句不符而新開的，這件事只有在 PR 連到 ADR 時才會發生。

4 · Billing 合併出帳需要把停車會話與充電會話對上——兩個契約有共同鍵嗎？升版哪個、加哪個欄位、為什麼是 v2？

沒有。charging.session.completed.v1 有 sessionId / connectorId 沒有 plate；parking.session.closed.v1 有 plate / parkingSessionId 沒有 sessionId。選項：charging.session.started.v1 升 v2 加 plate?（由 Parking ↔ Charging 的 Partnership 在插槍時對應 connector ↔ plate），或新增一個關聯事件。用 v2 而不是改 v1：既有消費者（Billing 草稿、Parking）依 v1 Schema 驗證，改 v1 會讓舊消費者與舊範例同時失效；contracts/README.md 規則 2「版本只能加欄位；改語意或刪欄位升 v2 並行一段時間」。加 optional 欄位嚴格說可以留在 v1，但「plate 從哪來、誰保證」是語意上的新承諾，所以本頁學員選 v2 並行。

5 · 你公司裡的一個「人當 API」交接點，用哪三個工具可以在 30 天內改成事件驅動？

  • retro 三個範本不一致：workshop/day7/TEMPLATE.md 的 retro 是「Keep / 卡最久三處 / 重來會做 / 助教用法」；/retro skill 與 sdlc.md 是 Start / Stop / Continue + 數字；rubric 要求 Start / Stop / Continue 各 ≥ 2 + 數字段。本頁把兩種合在一份（時間線表涵蓋「卡最久三處」，助教用法獨立一段）。講師要在 kickoff 說「兩個都要，合在一份」，否則 /checkout 會依 rubric 判學員的 TEMPLATE 版「不過」。
  • backlog 數量也不一致：day7.md 說「三件 + 技術債」，rubric 說 ≥ 6 項。本頁做 7 項 + 技術債。以 rubric 為準（rubric 自己說「兩邊不一致以本檔為準並回報講師」）——講師要把這個回報真的做掉。
  • 真實世界的故事：教材裡沒有任何「真的 OCPP 場站」的故事。講師要自備兩則：一則「transactionId 在樁重開機後從 1 重數，兩個月後撞號」（為什麼 sessionIdFor() 只能在 ACL、為什麼 sessionId 該由我們發）；一則「Faulted 狀態抖動：同一根樁 8 秒內報 3 次 GroundFailure」（R5 為什麼分「再申告」與「broker 重送」）。沒有這兩則，R5 與 ACL 對學員只是規則。
  • 公司例子：/takeaway 的映射需要學員說出自己公司的交接點；沒有經驗的學員（剛畢業）會答不出來。講師準備兩個自己的（本頁用的「客服問倉管」、「財務對帳」）當備援。
  • 最終評量太容易：10 題單選，每題有兩個明顯的稻草人選項；80% 幾乎人人過。真正的閘門是 rubric §3.3 的 15 分鐘口試與 §3.2 的一票否決（一行 grep）。講師要真的做口試，至少抽三題；/checkout day7 的自評分數只是參考。
  • Review 的「人」那一半：/review 做完，教材說「修完再請人看」，但一個人的工作坊沒有第二個人。講師若有時間，Day 7 下午花 10 分鐘 / 人做真人 review——只看 PR 描述能不能導航，不看 diff。這是整週唯一一次講師以 reviewer 身份出現，價值很高。

時間會不會爆：會，在 B3。B1 的 90 分鐘如果 /review 回 8 條而每條要補測試，實際只修得完 4–5 條（本頁的 7 條是理想值；4 條 🔴 + 1 條 🟠 是務實目標）。B2 的兩輪 CI 迭代各 4–6 分鐘，加上 PR 描述與 ADR 對帳，90 分鐘剛好。B3 的 retro + backlog + 評量 + takeaway 是四件事塞 90 分鐘：backlog 七條寫到有 GWT 至少 45 分鐘。建議：backlog 課堂只做三件必列 + 技術債各一條 GWT，其餘回家；「給主管的一頁」回家寫；評量可以在午休前先考。
