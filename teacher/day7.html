驗收看哪一行：(1) git log --oneline main..HEAD | head -12——要看到 test(...) 紅燈 commit 排在 fix(...) 之前（上面的 c94e11a → d02b7f5、e3a8c61 → f5c0d12）；只有 refactor 沒有 test 的，問「你怎麼知道重構沒改行為？」。(2) grep -rnE "new Date|publish\(|errorCode|StatusNotification" starter/node/src/charging/domain starter/node/src/assetops/domain 必須是空的——這一行 grep 就是 rubric §3.2 一票否決的自動版。(3) pr.md「沒修（理由）」段：理由要有「真正的修法 + 現在為什麼撐得住 + 去了哪裡」三件；只有「時間不夠」的不算。

常見失真：學員把 /review 的 8 條全修——90 分鐘修不完，最後全部半套、測試沒補。攔法：kickoff 就講「🔴 必修、🟠 二選一、🟡 進 backlog」。另一種：學員說「Claude 說要修我就修」，沒有一條反駁——review 是對話不是判決，至少要有一條學員說「不」而且理由成立（本頁的 #6）。第三種：學員要求 /review --fix，skill 會拒絕；如果學員繞過去用 /ta 幫我改，CLAUDE.md 的 TDD 規則會擋——但講師在教室裡聽到「幫我改」就要走過去。

怎麼攔「findings 是假的」：隨機挑一條 🔴，要學員在 30 秒內打開那個檔案指到那一行。指不到 = 表是生成的、沒有真的讀。

# CI for the EV Charge Ops workshop branch workshop/clarence.
# One workflow serves both languages: the `config` job reads workshop/.config (LANG=node | LANG=python)
# and builds the matrix with ONLY that starter, so the other one (still on its Day 1 red test) never runs.
name: ci

on:
  push:
    branches: ["main", "workshop/**"]
  pull_request:

# A new push to the same branch cancels the run that is still going.
concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

permissions:
  contents: read

jobs:
  config:
    # Decide which starter to test. Fails loudly if workshop/.config is missing or says something else.
    runs-on: ubuntu-latest
    timeout-minutes: 2
    outputs:
      matrix: ${{ steps.pick.outputs.matrix }}
      lang: ${{ steps.pick.outputs.lang }}
    steps:
      - uses: actions/checkout@v4
      - id: pick
        run: |
          lang=$(grep -E '^LANG=' workshop/.config | tail -1 | cut -d= -f2 | tr -d '[:space:]')
          case "$lang" in
            node)   matrix='{"include":[{"lang":"node","dir":"starter/node"}]}' ;;
            python) matrix='{"include":[{"lang":"python","dir":"starter/python"}]}' ;;
            *) echo "::error::workshop/.config must say LANG=node or LANG=python (got '$lang')"; exit 1 ;;
          esac
          echo "lang=$lang"     >> "$GITHUB_OUTPUT"
          echo "matrix=$matrix" >> "$GITHUB_OUTPUT"

  test:
    # Unit + application tests of the chosen starter. Dependencies are cached per lockfile.
    needs: config
    runs-on: ubuntu-latest
    timeout-minutes: 15
    strategy:
      fail-fast: false
      matrix: ${{ fromJSON(needs.config.outputs.matrix) }}
    defaults:
      run:
        working-directory: ${{ matrix.dir }}   # every `run` below executes inside starter/<lang>
    steps:
      - uses: actions/checkout@v4

      # --- node -------------------------------------------------------------
      - if: matrix.lang == 'node'
        uses: actions/setup-node@v4
        with:
          node-version: 22                      # scripts/e2e/run.mjs relies on Node 22 type stripping
          cache: npm
          cache-dependency-path: starter/node/package-lock.json   # NOT the repo root
      - if: matrix.lang == 'node'
        run: npm ci
      - if: matrix.lang == 'node'
        run: npm test                           # package.json: "test": "vitest run"
      - if: matrix.lang == 'node'
        run: npm run typecheck                  # tsc --noEmit

      # --- python -----------------------------------------------------------
      - if: matrix.lang == 'python'
        uses: actions/setup-python@v5
        with:
          python-version: "3.11"
          cache: pip
          cache-dependency-path: starter/python/requirements.txt
      - if: matrix.lang == 'python'
        run: pip install -r requirements.txt
      - if: matrix.lang == 'python'
        run: pytest -q                          # pyproject.toml sets pythonpath = ["src"]

  contracts:
    # Integration-event contracts (curriculum §1.8): every example must validate against its schema.
    # Runs for both languages — the contracts are shared and language-neutral.
    runs-on: ubuntu-latest
    timeout-minutes: 5
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
      - run: node contracts/validate.mjs

  e2e:
    # Optional (day7.md 延伸): boot the Day 6 HTTP API on SQLite in the background and replay
    # the canonical afternoon 14:02 → 18:18 against it. Start commands come from workshop/day6/README-mvp.md.
    needs: [config, test]
    runs-on: ubuntu-latest
    timeout-minutes: 10
    strategy:
      matrix: ${{ fromJSON(needs.config.outputs.matrix) }}
    env:
      DB_PATH: /tmp/e2e.sqlite
      PORT: "3000"
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: ${{ matrix.lang == 'node' && 'npm' || '' }}
          cache-dependency-path: ${{ matrix.lang == 'node' && 'starter/node/package-lock.json' || '' }}
      - if: matrix.lang == 'python'
        uses: actions/setup-python@v5
        with:
          python-version: "3.11"
          cache: pip
          cache-dependency-path: starter/python/requirements.txt

      - name: Start API (node)
        if: matrix.lang == 'node'
        working-directory: starter/node
        run: |
          npm ci
          nohup npm run start > "$RUNNER_TEMP/api.log" 2>&1 &
      - name: Start API (python)
        if: matrix.lang == 'python'
        working-directory: starter/python
        run: |
          pip install -r requirements.txt
          nohup python -m uvicorn adapters.http.server:app --app-dir src --port "$PORT" > "$RUNNER_TEMP/api.log" 2>&1 &

      - name: Wait for /health
        run: |
          for i in $(seq 1 30); do
            curl -fsS "http://localhost:$PORT/health" && exit 0
            sleep 1
          done
          echo "::error::API did not come up"; cat "$RUNNER_TEMP/api.log"; exit 1

      - name: Replay 14:02 → 18:18
        run: node scripts/e2e/run.mjs --url "http://localhost:$PORT"   # exit 1 if any final assertion fails

      - name: Upload API log on failure
        if: failure()
        uses: actions/upload-artifact@v4
        with:
          name: e2e-api-log-${{ matrix.lang }}
          path: ${{ runner.temp }}/api.log

講師註 · Block 2

驗收看哪一行：(1) ci.yml 的 cache-dependency-path——沒有這行或指到根目錄的，代表沒有真的在乾淨機器上跑過（本機 npm ci 不會告訴你）。(2) config job 或等價的條件——兩個語言 job 都無條件跑、而 Python 學員的 Node job 綠（因為 starter/node 的 Day 1 紅燈被 skip）的，問「你的 CI 綠是在證明什麼？」。(3) PR 描述「怎麼驗證」段有沒有具體指令 + 預期輸出（41 passed、7 valid、exit 0）；只有「跑測試」三個字的不過。(4) git log：ADR-0003 是新檔，ADR-0002 只加了一行參照——直接改 0002 內文的，問「三個月後誰知道它曾經寫錯？」。

常見失真：ci.yml 整份請 Claude 生。攔法：指著任一行問為什麼（本頁的 fromJSON、tr -d '[:space:]'、node-version: 22）。另一種：PR 描述貼 sdlc.md §4 範本連數字都沒改（47 passed 是範本的數字；本頁學員是 41）。第三種：base 開到 main——整合分支 workshop-submissions 要講師事先建好並在 kickoff 說。

時間：每次 CI 紅→修→push→等，實際 4–6 分鐘；預算兩輪。超過三輪紅的學員通常是 SQLite 驅動在 ubuntu-latest 編譯失敗（day7.md 卡點有寫：改 node:sqlite 或 DB_PATH=:memory:）——這時講師直接給答案，不要讓他耗掉 Block 3。
