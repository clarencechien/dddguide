1. ChargingSession 聚合

  • 聚合根：ChargingSession，也是聚合的全部（沒有子實體）。
  • 識別：connectorId（CP-A12-2）。一把槍一個聚合；sessionId（S-991）是它進入 Charging 後的一段狀態。這樣 R1「一個連接器同時只有一個進行中會話」是純聚合內的不變條件：第二次 start 看自己的 status 就知道占用，不用查 repository。代價：一把槍的歷史會話不在這個聚合裡（那是查詢 / 事件的事）。
  • 狀態機（Mermaid，與上圖一致）：

3. WorkOrder 聚合（R5）

  • 識別：workOrderId（WO-2208）。持有 chargerId（CP-A12）與 faultCode（GroundFailure）字串，不持有 Charger 物件。
  • 狀態：Open → Assigned → Closed；「開放期間」= isOpen = 非 Closed。
  • 欄位：workOrderId, chargerId, faultCode, connectorId?, openedAt, reports: string[]（每次申告的 occurredAt，含第一次）、status, technicianId?, outcome?。duplicateReportCount = reports.length − 1。
  • 方法 / 事件：open() → WorkOrderOpened；appendDuplicateReport(at) → DuplicateFaultReported（R5，只在 isOpen；關單後 throw）；assign(TECH-HAO, at) → TechnicianAssigned；close(outcome, at) → WorkOrderClosed；pullEvents()。
  • R5 的分層：「同樁同碼、開放期間、是否已有工單」需要查其他工單 = I/O，聚合做不到。所以：port WorkOrderRepository.findOpenByFault(chargerId, faultCode) 負責查；應用層（Day 5 的 FaultProcessManager）決定開新單或呼叫既有單的 appendDuplicateReport；聚合只負責「開放期間才能附加」與記錄事件。去重鍵 = chargerId + faultCode（§1.8）。
