6. 不准出現的關係

  • Billing → Charging 回呼（凍結 / 鎖住會話等算錢）：違反 Customer–Supplier 與 §1.1 斷線存活。
  • AssetOps / Dispatch → Billing「技術員已出發」：維修成本不進顧客帳單；帳務只訂閱 session.* 與 parking.session.closed。
  • OCPP 直連任何 domain：StatusNotification、idTag、transactionId 只能出現在 src/adapters/ocpp/。
  • Charging 呼叫總部 API 才能 Start / Stop：授權與計量是場站本機責任；總部只訂閱結果。
  • 任何 Shared Kernel（共用 schema、共用 ORM model）：contracts/*.json 是 Published Language，不是共享核心。
  • Dispatch ↔ Billing 任何直接邊：各走各的。

7. 我推翻過的切法

  • 第一版（白板）：兩堆——場站 / 總部。推翻理由：那是部署位置。「場站」裡阿忠的放行與小美的授權用的詞、守的規則都不一樣；「總部」裡老陳月底才工作，跟 Vicky 每天派工不是同一群人。
  • 第二版（B1 第 40 分鐘）：三堆——場站（停車 + 充電）、維運（工單 + 派工）、帳務。推翻理由：（a）語言衝突 + 生命週期——P-441 14:02–14:33 與 S-991 14:04–14:31 是兩種會話，一對多；（b）一致性——R1 守的是連接器不是車位，「一個車位一輛車」與「一個連接器一個會話」是兩條不變條件；（c）一致性節奏——R5 要在 18:10:08 立刻擋，派工回報要等阿豪從地下室上來；（d）漏掉 OCPP 該放哪——它不是 context，是要被 ACL 隔開的外部協定。
  • 第三版（最終）：五個。保留「三堆」版本的代價紀錄：如果 Sprint 2 Dispatch 仍是 stub，把 AssetOps 與 Dispatch 合成一個 context 是可接受的簡化，但要在 ADR-0001 的替代方案裡留著。

8. 與課綱 §1.4 的差異（B2 對照後才填）
